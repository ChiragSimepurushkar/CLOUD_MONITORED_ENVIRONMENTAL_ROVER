# Cloud-Monitored Environmental Rover

A full-stack IoT system featuring an autonomous, room-scanning robotic rover, a real-time 3D web dashboard, and a mobile application for manual override. The system uses an Arduino-based rover equipped with environmental sensors and an ultrasonic scanner to map its surroundings and report data to a Node.js/Express backend via an ESP8266 Wi-Fi module.

## Features

*   **Autonomous Room Scanning**: The rover drives autonomously, avoids obstacles, and performs a 7-angle ultrasonic sweep at regular intervals or when encountering an obstacle.
*   **Environmental Monitoring**: Collects temperature, humidity (DHT11), and gas concentration (MQ sensor) data.
*   **Real-time 3D Dashboard**: A React-based web interface featuring a 3D occupancy grid map, live sensor charts, and connection analytics, built with `recharts` and custom grid engine logic.
*   **Mobile App Control**: An Android app (built with MIT App Inventor) allows users to view live sensor data, switch between autonomous and manual modes, and drive the rover via a digital D-pad.
*   **Optimized Network Protocol**: Single-TCP-connection architecture (merged polling and uploading) prevents ESP8266 timeout errors and ensures reliable communication.

## Hardware Architecture

### Components
*   **Arduino UNO** (Core controller)
*   **ESP8266 (ESP-01)** (Wi-Fi communication)
*   **L298N / AFMotor Shield** (Motor control)
*   **4x DC Motors** (4WD chassis)
*   **HC-SR04 Ultrasonic Sensor** (Distance measurement & mapping)
*   **Servo Motor (SG90)** (Pans the ultrasonic sensor for sweeping)
*   **DHT11** (Temperature & Humidity)
*   **MQ Gas Sensor** (Air quality/smoke detection)

### Wiring Overview
*   **Motors**: Connected to AFMotor Shield M1, M2, M3, M4.
*   **Servo**: Attached to Pin 10.
*   **HC-SR04**: `TRIG_PIN` = A0, `ECHO_PIN` = A1.
*   **MQ Sensor**: Analog Pin A2.
*   **DHT11**: Analog Pin A3.
*   **ESP8266**: Connected via SoftwareSerial on A4 (RX) and A5 (TX).

## Software Architecture

### 1. Arduino Firmware (`rover_arduino.ino` v4.5)
The firmware handles sensor reading, motor control, obstacle avoidance, and network communication.
*   **Single-TCP Architecture**: The rover POSTs sensor and scan data to the server, and the server's HTTP response contains the next command (`auto` or a manual direction). This eliminates the need for separate GET polling connections, resolving the notorious "ESP8266 closed connection early" error.
*   **Dead Reckoning**: Tracks the rover's estimated X, Y coordinates and heading based on motor timing.

### 2. Node.js Backend (`server.js` v4.1)
An Express and Socket.IO server backed by MongoDB.
*   **Endpoints**:
    *   `POST /rover-data`: Receives data from the Arduino. Uses a custom raw body reader to gracefully handle partial/aborted connections from the ESP8266 without crashing or spamming logs.
    *   `GET /data`: Used by the MIT App to fetch the latest sensor readings and mode status.
    *   `GET /control?cmd=...`: Receives manual driving commands from the MIT App.
    *   `GET /auto?toggle=...`: Toggles autonomous mode.
*   **Grid Engine (`gridMap.js`)**: Uses Bresenham's line algorithm to process the 7-angle ultrasonic sweeps into a 2D occupancy grid, calculating free space vs. walls.
*   **Socket.IO**: Broadcasts real-time updates (`raw-data`, `map-update`, `chart-update`) to the web dashboard.

### 3. React Frontend (`frontend/`)
A sleek, dark-themed, modern web application.
*   **Dashboard**: Live vital stats, connection health, and current rover status.
*   **3D Map**: Visualizes the occupancy grid generated by the backend, rendering clear paths, walls, and the rover's trajectory.
*   **Analytics**: Historical charts (using `recharts`) of temperature, humidity, gas, and distance over time.

### 4. MIT App Inventor Mobile App
Provides a handheld remote control for the rover.
*   **Components**: A dashboard for sensor values, a mode toggle button, and a 3x3 layout arrangement forming a D-pad (Forward, Backward, Left, Right, Stop).
*   **Interaction**: Polling the backend every 2 seconds for sensor updates, and sending HTTP GET requests to control the rover's movements.

## Setup & Installation

### Step 1: Backend Server Setup
1. Install Node.js (v16+ recommended).
2. Install MongoDB and ensure it is running locally, or provide a cloud URI in a `.env` file (`MONGO_URI`).
3. Navigate to the `backend/` directory:
   ```bash
   cd backend
   npm install
   ```
4. Start the server:
   ```bash
   node server.js
   ```
5. **Important**: Note the Network IP Address printed in the terminal (e.g., `http://192.168.0.104:5000`). You will need this for both the Arduino code and the MIT App.

### Step 2: React Frontend Setup
1. Navigate to the `frontend/` directory:
   ```bash
   cd frontend
   npm install
   ```
2. Start the development server:
   ```bash
   npm start
   ```
3. The dashboard will open in your browser at `http://localhost:3000`.

### Step 3: Arduino Setup
1. Open `rover_arduino/rover_arduino.ino` in the Arduino IDE.
2. Install required libraries via the Library Manager: `AFMotor`, `NewPing`, `Servo`, `DHT sensor library`.
3. Configure your Network Settings at the top of the file:
   ```cpp
   const char SSID[]      = "Your_WiFi_Name";
   const char PASS[]      = "Your_WiFi_Password";
   const char SERVER_IP[] = "192.168.0.104";  // <-- Replace with your Laptop's IP
   ```
4. Upload the sketch to the Arduino UNO.

### Step 4: MIT App Inventor Setup
1. Open MIT App Inventor and create/import your project.
2. Ensure the layout matches the 3x3 D-Pad configuration.
3. Update the URLs in the blocks to match your backend IP (e.g., `http://192.168.0.104:5000/data` for the timer, and `http://192.168.0.104:5000/control?cmd=forward` for buttons).
4. Build the `.apk` and install it on your Android device.

## Troubleshooting

*   **ESP8266 Not Connecting**: Ensure your Wi-Fi network is 2.4GHz (ESP8266 does not support 5GHz). Double-check the SSID and password. Ensure the ESP-01 is receiving adequate power (it often requires a separate 3.3V regulator, not just the Arduino's 3.3V pin).
*   **"ESP8266 closed connection early" Logs**: This was a common issue in older firmware versions due to `delay()` loops during transmission. Upgrading to `rover_arduino.ino` v4.5 and `server.js` v4.1 resolves this by using raw body parsing and a merged POST/Poll TCP connection.
*   **App Commands Not Responding Immediately**: The rover only checks for manual commands when it stops to scan (autonomous mode) or every 5 seconds (manual idle mode). This is a limitation of the single-threaded Arduino handling Wi-Fi.
